> 正式 SDD 产物已补充到 `specs/001-mira-mvp/`。后续实现优先使用 `specs/001-mira-mvp/spec.md` 和 `specs/001-mira-mvp/tasks.md` 作为需求与任务事实源；本文件保留为详细背景和历史实施路线。

> 给后续 Agent 工作者：实施本计划时优先使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`。本文件使用 checkbox 语法追踪进度。

## 0. 重新定位

Mira 的 MVP 不追求成为 Rowboat、Khoj、AnythingLLM、mem0 或 Supermemory 的替代品。

Mira 的第一目标是更窄的：

> 为一个开发项目提供本地连续记忆，让不同 AI 编程 Agent 能接着上一次工作继续，而不是重新询问项目背景、重复失败尝试或遗忘近期决策。

因此 MVP 聚焦一条闭环：

```text
Thread 保存
  -> Memory 提炼 / 手动写入
  -> Working Memory 维护
  -> Memory 搜索
  -> Context Bundle 输出
  -> CLI / MCP 注入给 Agent
  -> Agent 工作后回写 Thread / Memory
```

## 1. 产品边界

### 第一用户

这台机器的拥有者，以及在本机项目中工作的 Codex、Claude Code、Cursor、OpenClaw 等开发者 Agent。

### 第一承诺

当用户在不同 Agent、不同会话之间切换时，Agent 能快速恢复项目上下文，知道：

- 这个项目是什么。
- 当前正在做什么。
- 最近做过哪些决策。
- 哪些做法已经失败过。
- 用户偏好和项目约定是什么。
- 下一步最可能应该继续哪里。

### MVP 做什么

- 保存 Agent 会话为项目关联 Thread。
- 从 Thread 中提炼长期有效的项目 Memory。
- 支持人类和 Agent 手动写入 Memory，作为 distill 失效时的兜底。
- 维护当前项目的 Working Memory。
- 搜索当前项目 Memory。
- 生成短小可注入的 Context Bundle。
- 通过 CLI 暴露保存、提炼、写入、搜索、上下文生成和导出能力。
- 通过 MCP stdio server 暴露 Agent 可调用工具，包括读上下文和回写经验。
- 使用 SQLite + FTS5 作为本地存储与搜索基础。
- 自动从当前目录向上探测 Git 项目根目录。
- 支持 Markdown / raw text 作为第一批导入格式，并在 Thread 中记录 `raw_format`。
- 提供 Agent 配置示例和 AGENTS.md 行为引导模板。

### MVP 不做什么

- 不做完整桌面 AI coworker。
- 不做邮件、会议、Slack、浏览器控制等大集成。
- 不做通用消费者个人记忆。
- 不做多用户、团队空间、云同步、计费。
- 不做插件市场。
- 不先做图谱 UI。
- 不先做向量数据库，除非 FTS 闭环跑通后有明确痛点。

### Post-MVP 明确延后

- Codex JSONL、Claude transcript、Cursor 导出等多格式导入适配器。
- Tag、Relation、Source 独立实体与完整知识图谱。
- LLM 智能提炼、归并、冲突检测和置信度评分。
- 文件级 failure heatmap、precheck、git hook 等治理能力。
- Dashboard / TUI / Desktop UI。
- 跨项目全局记忆。

## 2. MCP 项目绑定策略

MVP 采用“每项目一个 Mira stdio server”的模型，不做全局常驻服务。

### 决策

- 数据库默认放在项目内 `.mira/mira.sqlite`。
- `mira mcp serve` 启动时必须绑定一个项目根目录，推荐显式传入 `--project-root /abs/path/to/project`。
- `mira mcp serve` 启动时推荐显式传入绝对数据库路径：`--db /abs/path/to/project/.mira/mira.sqlite`。
- MCP 工具入参可以携带 `projectRoot`，但未传时使用 server 启动时绑定的项目。
- 如果探测出的项目根目录在数据库中不存在，Mira 自动创建 Project，名称使用根目录 basename。
- `mira project add --name X --root /path` 用于显式创建或更新项目名称；其他命令不要求用户先手动 add。
- Agent 配置示例必须使用绝对路径，不能依赖 MCP client 的当前工作目录。
- 全局 `~/.mira/mira.sqlite` 和多项目统一服务放到 post-MVP。

### 影响

这让 MVP 的心智模型保持简单：一个 repo 有一个 `.mira/`，一个 MCP server 服务一个 repo。Agent 不需要猜项目，Mira 也不需要在 MVP 中解决跨项目路由和权限隔离。

## 3. 核心数据模型

### Project

项目空间。Mira 的所有 Thread、Memory、Working Memory 都必须属于某个 Project。

核心字段：

```text
id, name, root_path, created_at
```

项目解析规则：

- 显式传入 `--project-root` 时使用该路径。
- 未传时使用 `detectProjectRoot(process.cwd())`。
- 数据库中找不到该 root 时自动创建 Project，名称使用目录名。
- `mira project add` 可以显式设置或更新项目名称。

### Thread

一次原始 Agent 会话。Thread 保留原文，用于重新提炼、审计和回溯。

核心字段：

```text
id, project_id, title, source, raw_format, raw_text, created_at, updated_at
```

`raw_format` MVP 取值：

```text
markdown, text
```

后续导入 Codex JSONL、Claude transcript、Cursor 导出时扩展为：

```text
jsonl, transcript, cursor_export
```

### Memory

长期项目记忆。Memory 是从 Thread 中提炼出来，或由人类 / Agent 手动写入的、可搜索、可注入上下文的事实或判断。

核心字段：

```text
id, project_id, thread_id, title, kind, content, source, confidence, content_hash, importance, created_at
```

字段说明：

- `title`：短标题，用于搜索结果和 Context Bundle 展示。
- `source`：记忆来源，例如 `distill`、`manual`、`mcp`、`import`。
- `confidence`：置信度，确定性规则和手动写入默认 `1.0`，未来 LLM 提炼可低于 `1.0`。
- `thread_id`：可为空。手动写入的 Memory 可以没有来源 Thread。
- `content_hash`：用于幂等写入和去重。

MVP 支持的 `kind`：

```text
decision, convention, architecture, preference, task, fact, failed_attempt
```

### Working Memory

当前项目工作快照。它不是历史归档，而是 Agent 接手项目时最先读取的“现在状态”。

核心字段：

```text
id, project_id, kind, content, updated_at
```

MVP 支持的 `kind`：

```text
current_task, current_phase, recent_decision, blocker, next_step, preference
```

MVP 规则：

- `project_id + kind` 保留一条最新记录。
- 如果某类信息天然有多条，例如多个 blocker 或 next_step，`content` 使用 Markdown 列表。
- 这样 Context Bundle 始终短小，且 Agent 不需要合并多条当前状态。

### SearchResult

搜索接口统一返回结构，CLI 和 MCP 都基于它展示：

```ts
type SearchResult = {
  memory: Memory;
  score: number;
};
```

`score` 是归一化后的相关性分数，数值越高表示匹配越强。MVP 从 SQLite FTS5 rank 转换得到；后续切换 hybrid/vector 检索时保持接口不变。

### Context Bundle

Context Bundle 不是数据库实体，而是输出格式。它必须满足：

- Markdown。
- 短小。
- 先 Working Memory，后长期 Memory。
- 可设置条数限制和粗略 token 预算。
- 优先展示 Memory `title`，必要时展示 `content`。
- 可直接贴进 Agent 会话，也可由 MCP 返回。

## 4. 技术栈

- TypeScript + Node.js。
- SQLite + FTS5。
- `better-sqlite3`。
- `commander`。
- `vitest`。
- `tsx`。
- MCP TypeScript SDK。

MVP 不引入 Web 框架、Electron、向量数据库、消息队列或远程服务。
