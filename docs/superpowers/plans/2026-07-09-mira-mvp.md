# Mira MVP 实施计划

> 给后续 Agent 工作者：实施本计划时优先使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`。本文件使用 checkbox 语法追踪进度。

## 0. 重新定位

Mira 的 MVP 不追求成为 Rowboat、Khoj、AnythingLLM、mem0 或 Supermemory 的替代品。

Mira 的第一目标是更窄的：

> 为一个开发项目提供本地连续记忆，让不同 AI 编程 Agent 能接着上一次工作继续，而不是重新询问项目背景、重复失败尝试或遗忘近期决策。

因此 MVP 聚焦一条闭环：

```text
Thread 保存
  -> Memory 提炼
  -> Working Memory 维护
  -> Memory 搜索
  -> Context Bundle 输出
  -> CLI / MCP 注入给 Agent
```

## 1. 产品边界

### 第一用户

这台机器的拥有者，以及在本机项目中工作的 Codex、Claude Code、Cursor、OpenClaw 等开发者 Agent。

### 第一承诺

当用户在不同 Agent、不同会话之间切换时，Agent 能快速恢复项目上下文，知道：

- 这个项目是什么。
- 当前正在做什么。
- 最近做过哪些决策。
- 哪些做法已经失败过。
- 用户偏好和项目约定是什么。
- 下一步最可能应该继续哪里。

### MVP 做什么

- 保存 Agent 会话为项目关联 Thread。
- 从 Thread 中提炼长期有效的项目 Memory。
- 维护当前项目的 Working Memory。
- 搜索当前项目 Memory。
- 生成短小可注入的 Context Bundle。
- 通过 CLI 暴露保存、提炼、搜索、上下文生成能力。
- 通过 MCP stdio server 暴露 Agent 可调用工具。
- 使用 SQLite + FTS5 作为本地存储与搜索基础。
- 自动从当前目录向上探测 Git 项目根目录。
- 支持 Markdown / raw text 作为第一批导入格式。

### MVP 不做什么

- 不做完整桌面 AI coworker。
- 不做邮件、会议、Slack、浏览器控制等大集成。
- 不做通用消费者个人记忆。
- 不做多用户、团队空间、云同步、计费。
- 不做插件市场。
- 不先做图谱 UI。
- 不先做向量数据库，除非 FTS 闭环跑通后有明确痛点。

### Post-MVP 明确延后

- Codex JSONL、Claude transcript、Cursor 导出等多格式导入适配器。
- Tag、Relation、Source 独立实体与完整知识图谱。
- LLM 智能提炼、归并、冲突检测和置信度评分。
- 文件级 failure heatmap、precheck、git hook 等治理能力。
- Dashboard / TUI / Desktop UI。
- 跨项目全局记忆。

## 2. 核心数据模型

### Project

项目空间。Mira 的所有 Thread、Memory、Working Memory 都必须属于某个 Project。

核心字段：

```text
id, name, root_path, created_at
```

### Thread

一次原始 Agent 会话。Thread 保留原文，用于重新提炼、审计和回溯。

核心字段：

```text
id, project_id, title, source, raw_text, created_at, updated_at
```

### Memory

长期项目记忆。Memory 是从 Thread 中提炼出来的、可搜索、可注入上下文的事实或判断。

核心字段：

```text
id, project_id, thread_id, kind, content, content_hash, importance, created_at
```

MVP 支持的 `kind`：

```text
decision, convention, architecture, preference, task, fact, failed_attempt
```

### Working Memory

当前项目工作快照。它不是历史归档，而是 Agent 接手项目时最先读取的“现在状态”。

核心字段：

```text
id, project_id, kind, content, updated_at
```

MVP 支持的 `kind`：

```text
current_task, current_phase, recent_decision, blocker, next_step, preference
```

### Context Bundle

Context Bundle 不是数据库实体，而是输出格式。它必须满足：

- Markdown。
- 短小。
- 先 Working Memory，后长期 Memory。
- 可设置条数限制和粗略 token 预算。
- 可直接贴进 Agent 会话，也可由 MCP 返回。

## 3. 技术栈

- TypeScript + Node.js。
- SQLite + FTS5。
- `better-sqlite3`。
- `commander`。
- `vitest`。
- `tsx`。
- MCP TypeScript SDK。

MVP 不引入 Web 框架、Electron、向量数据库、消息队列或远程服务。

## 12. 推荐执行顺序

1. 先完成阶段 1，确保项目可运行、可测试、本地数据库可迁移。
2. 再完成阶段 2，跑通 Project -> Thread -> Memory 的长期记忆基础闭环。
3. 然后完成阶段 3，把 Working Memory 和 Context Bundle 做成 Agent 接手项目的第一入口。
4. 再完成阶段 4，把能力暴露给人类 CLI。
5. 再完成阶段 5，把能力暴露给 Agent MCP。
6. 最后完成阶段 6，用真实会话验证闭环。

## 13. 自检

- 定位是否清楚：Mira 是项目级连续记忆层，不是通用 AI 工作台。
- 范围是否收窄：MVP 只做本地存储、Thread、Memory、Working Memory、Context Bundle、CLI、MCP。
- 日常可用性是否覆盖：自动项目探测、去重、schema 版本、MCP stdio、Agent 配置示例都在计划内。
- 后续扩展是否留口：Tag、Relation、Source、多格式导入、LLM 提炼、图谱 UI 都明确延后。
- 验收是否可执行：每个阶段都有测试或命令级验证。
