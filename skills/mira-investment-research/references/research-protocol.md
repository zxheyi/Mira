# Evidence → Claim → Review protocol

## 研究状态

- `observed`：来源中可直接观察到的事实，保留时间和范围。
- `supported`：现有证据足以支持限定后的主张。
- `contested`：可靠来源存在冲突，或关键反证尚未解决。
- `unsupported`：缺少直接证据，或只有推测和二手转述。
- `rejected`：证据与主张矛盾，或主张已被更新事实取代。

## 证据账本

每项证据记录：

| 字段 | 内容 |
| --- | --- |
| ID | `E<n>` |
| 来源 | 原始 URL、文件、公告、财报页码或数据集定位 |
| 类型 | 监管披露、公司原始材料、市场数据、研究论文、二手分析 |
| 时间 | 发布、报告期和访问时间；缺失项明确写未知 |
| 摘要 | 与问题直接相关的可核验事实 |
| 方向 | supports / contradicts / contextual |
| 边界 | 样本、口径、币种、调整项、可比性和已知缺口 |

优先使用监管披露、公司原始材料、交易所或数据提供方的一手数据。二手分析用于发现线索和不同解释；决定性主张需要回到可核验来源。Mira 中召回的旧 Memory 只提供检索线索，除非其 provenance 在本轮重新核验。

## 主张矩阵

每项主张记录：

| 字段 | 内容 |
| --- | --- |
| ID | `C<n>` |
| 主张 | 限定对象、时间、范围与比较基准的单一陈述 |
| 支持 | 直接支持它的 `E<n>` |
| 反证 | 与它冲突或削弱它的 `E<n>` |
| 状态 | observed / supported / contested / unsupported / rejected |
| 置信度 | 对当前证据充分度的判断，不是批准信号 |
| 失效条件 | 哪个新事实、阈值或日期会要求重审 |
| Thesis 影响 | none / watch / strengthen / weaken / invalidate；始终是待审核建议 |

一个来源相关不代表它支持主张。逐项检查证据是否真的蕴含该结论，并收窄超出证据的因果、范围和确定性。

## 审核门

按顺序检查：

1. 来源完整性：定位、日期、版本和口径可复核。
2. 主张蕴含：证据直接支持限定后的陈述。
3. 反证覆盖：最强反例和来源冲突已展示。
4. 时间一致性：没有用过期数据代表当前状态。
5. 风险检查：估值、会计口径、流动性、监管和数据缺口已显式记录。
6. 权限检查：研究包只提出 thesis 影响；批准和状态变更由领域协议或人执行。

任一检查失败时，把主张保留为 contested 或 unsupported，并列出解除条件。

## 审核包

交付顺序：

1. 研究问题与截至日期
2. 结论摘要及其状态
3. 证据账本
4. 主张矩阵
5. 反证与替代解释
6. Thesis 影响建议
7. 未决问题、失效条件和下一步
8. Mira 运行记录：taskId、recall/capture/persistence 状态、candidate ID（如有）

稳定的研究方法、来源约束或已核验的原始事实可以进入 Mira candidate。推导性投资结论、目标价和仓位建议保留在审核包，直到领域协议批准。
