# Recall quality baseline

状态：Approved
日期：2026-09-01

## 目标

建立一个可重复、无网络、无真实数据写入的 20 题召回基线，用来观察 Mira 当前词法检索在精确术语和语义改写下的表现。基线用于比较后续检索改动，并以批准的初始结果作为 CI 回归下限；它不把测试语料写入用户数据库，也不授权扩大自动写入范围。

## 接口与事实源

- `cases.json` 是题目、种子 Memory 与期望目标的唯一事实源。
- `runRecallBaseline(cases)` 在内存 SQLite 中通过正式 curation 接口写入种子，再通过 `searchMemories` 查询。
- 每题最多取 5 个结果，记录目标排名；未命中记为 `null`。
- 汇总指标为 `Recall@1`、`Recall@5` 与平均倒数排名（MRR）。
- 结果包含题目 ID、查询、期望目标、排名和返回目标键，不包含真实 transcript 或用户 Memory。

## 题集设计

题集覆盖 SQLite 事实源、接入适配、上下文准备、候选审核、派生输出、确认权限、召回审计、会话检查点、历史导入、批量替换、任务隔离、Briefing、Vault、隐私与投资研究协议。前 15 题保留关键术语，后 5 题使用语义改写，用于显式暴露无 embedding 时的召回缺口。

## 验收

- 题集恰好 20 题，ID 和目标键唯一，种子类型合法。
- 同一题集重复运行得到相同目标排名与指标。
- `npm run benchmark:recall` 输出机器可读 JSON。
- `Recall@1`、`Recall@5` 与 `MRR` 的批准回归下限均为 `0.75`；任一指标低于下限时命令以非零状态退出。
- GitHub CI 的独立 `Research invariants` job 运行目标架构、单案例、多案例研究验证和召回回归门禁。
- 自动测试验证报告结构、计分一致性和重复 ID 拒绝。
- `npm test`、`npm run build` 与 `git diff --check` 通过。

## 初始结果

2026-09-01 在当前词法检索实现上连续运行 5 次，结果一致：

- `Recall@1 = 0.75`
- `Recall@5 = 0.75`
- `MRR = 0.75`
- 5 个未命中均为语义改写题：低风险自动接受、注入不等于使用、旧 transcript 防护、证据约束研究结论、thesis 变更层。

这个结果既是后续检索改动的比较基线，也是防止已知能力退化的 CI 下限；下一轮优化仍应优先验证语义召回或重排，不应先扩大自动写入权限。
